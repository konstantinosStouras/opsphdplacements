## Data

`data/faculty.json` holds all 2,149 profiles from the OM List all-faculty snapshot of 16 October 2026 across 202 institutions. Source status (active, industry, retired or deceased) is preserved. PhD information is joined by exact source profile URL. `data/placements.json` holds independently verified first placements and contains the reviewed first-employer records published so far. Never infer a first placement from a directory affiliation. `data/faculty-roster-people.json` is the second source of people (built by `node scripts/build-roster-people.mjs` from the roster reviews): the 1,007 people whom a reviewer confirmed as academic staff on their own university page and whose area or title shown names an operations field, in the same record shape with `source: "faculty-page"`, the profile page as `sourceProfileUrl`, the doctorate only as that page states it (with `phdInstitutionSourceUrl`) and a discipline label derived from the department name. The explorer, the coverage figures, the institution profiles and the research ledger (`data/research-status.json`, one entry per person of both sources, `bySource` in its metadata) treat both sources alike; their first jobs are researched with the same rules and published in `data/placements.json`. `data/institution-aliases.json` lists the reviewed written forms of PhD institutions (abbreviations such as "MIT", short forms such as "Princeton", spelling variants and schools such as "The Wharton School") that count as an institution already in the people database; each person keeps the written form in `phdInstitutionAsWritten`.

See [DATA-PROVENANCE.md](DATA-PROVENANCE.md) for source reconciliation, reproducible import commands and limitations. The source does not cover Industrial Engineering departments; its discipline labels do not verify the subject of someone's doctoral degree.

## Checks and publication

Run `npm run check` with Node 22 or later. There are no application dependencies. The publishing script copies public files and versions assets to prevent stale pages after updates. Checks cover dataset identity and provenance, filtering, missing years, grouped counts, and safe CSV export. Every production deployment runs these checks. Only public assets are deployed; research snapshots, import tools and test fixtures are excluded.

Preview with a static server, inspect changes and commit the reviewed data. A push to `main` validates and publishes the site. Roll back by reverting a commit and pushing; never overwrite history. No scheduled scraping is configured.

## Data contracts

Every record in every database carries `addedAt` (when it first appeared) and `updatedAt` (its last change), UTC date-times kept by `scripts/record-dates.mjs` from the ledger `data/record-dates.json`; both remain in the underlying records. Faculty records require a unique stable `id`, `name`, `sourceUrl`, and `retrievedAt`. Unknown degree facts are null; a future doctorate year is flagged. Retain original source labels and source URLs. Faculty affiliation is not a placement outcome.

First-placement records additionally require `verificationStatus: "verified-first-placement"`, `evidenceUrl`, `reviewedAt`, and an explicitly known `placementYear` or null. Review the explicit first-job evidence before adding any record. Imported degree fields remain source-reported unless the corresponding field verification status says otherwise; verifying a job does not verify every directory fact.

`data/institution-locations.json` holds an approximate map location for each imported PhD institution, matched by name to a Wikidata item (its ID, label and description are kept so matches can be checked), plus the path of its logo under `assets/logos/` (192 px PNG; the institution's seal, coat of arms, logo or site icon, laid out to fill the map circle; see WORKFLOW.md). Unmatched or ambiguous names stay unmapped and are counted on the map, never guessed. Regenerate with `node scripts/geocode-institutions.mjs` and `node scripts/fetch-institution-logos.mjs`; both are slow because Wikidata rate-limits anonymous clients. `data/universities.json` is the first of the project's two databases: universities, schools and departments that do Operations, imported from the Operations Academia directory by `node scripts/import-operations-academia.mjs`, each linked where possible to its PhD institution in the people database with the match type recorded (see RESEARCH-DESIGN.md). `data/entities.json` merges the two databases and the program register into one record per organisation (`node scripts/build-entities.mjs`, run last): keyed by Wikidata item where known, otherwise by name; every name from either source is an alias; the people figures, directory departments, first-employer figures and programs sit side by side and nothing is inferred across sources; `npm run check` fails if any PhD institution, directory university or first employer is missing from it or attached twice. `data/location-review.json` holds the reviewed corrections to the name-based Wikidata matches (the right item, or no item for an ambiguous name, with the reason and date), which `node scripts/geocode-institutions.mjs` applies to all three location files; `data/university-locations.json` places the directory universities the same way. In every derived file, names that differ only in accents, punctuation, spacing or case are one organisation, with the variants listed under `spellings`. `data/faculty-rosters.json` lists the people shown on the faculty pages that the universities database links (`node scripts/collect-faculty-rosters.mjs fetch` then `build`): each person with the title shown, the page and retrieval date, the OM List profile when the name and university match (with that profile's source-reported doctorate, research status and verified first job), and otherwise `verification: "unverified"` with a null doctorate and first job until a reviewer's outcome is merged by `node scripts/merge-roster-research.mjs` (the one-by-one pass of 16 October 2026 reviewed everyone without an OM List match whose title did not say student, staff or postdoc: the outcome, the opened pages, the title and area shown and, when a page states it, the doctorate with its URL; `node scripts/update-roster-notes.mjs` rewrites the review position in the guides); the file also reports every linked page's fetch status. A listing establishes only that the page showed the name under that title (see RESEARCH-DESIGN.md). `data/institutions.json` and `data/employers.json` are derived databases regenerated by `node scripts/build-institutions.mjs`: one row per PhD institution (people in the directory, verified first jobs, unresolved and pending counts, cohort range, first-job types, top first employers, location, country, icon and sources) and one row per verified first employer (verified first jobs, source institutions, positions, cohorts, location, country). They are never edited by hand, and `npm run check` fails if their totals disagree with the public files. `data/graduate-lists.json` holds the names that the programs' own placement, alumni and graduate pages list by year, read live and from archived snapshots (`node scripts/collect-graduate-lists.mjs`, `node scripts/merge-graduate-lists.mjs`; one record per person, institution and listed year, every snapshot kept as a sighting with its URL and date, the year's meaning as the page gives it, the area the page states classified as operations, another field or unstated, and a link to the people database only where name and PhD institution both match); the Graduates section of the site shows them with institution, area and search filters. `data/doctoral-programs.json` holds the partial historical program register, with field-level sources/check dates and explicit unknown historical dates. It does not yet contain complete graduate rosters. Refresh `RESEARCH-STATUS.md` with `node scripts/update-research-status.mjs` when publishing data changes. Run `python scripts/test-research-schema.py` and `python scripts/build-research-database.py` for the relational evidence checks and reproducible snapshot.

## Features

University results sort alphabetically by displayed name, including filtered results and subsequent pages. Prose, generated summary-card descriptions and table text use shared justification with hyphenation; short final lines remain naturally spaced.

Individual Chrome reviews of university identities and operations units are stored in `data/university-reviews.json`, separately from the preserved directory import. The university table and organisation profiles display verified units with official evidence, check dates and review limitations. Original labels and reconciliation decisions remain collapsed for audit; pending records are labeled explicitly. A verification filter separates completed, partial, blocked and pending records. Reviewed university aliases consolidate only through explicit source-backed IDs. See the [review contract](research-handoff/universities/CONTRACT.md) and [assignments](research-handoff/universities/assignments.json); the 645-record review is in progress.

The top menu sits on one line next to the title on screens wider than 950 px (it wraps below the title on phones); a thin blue line along the very top of the window shows how far down the page the reader is, and the menu link of the section in view turns blue. The coverage section opens with an interactive world map of PhD-granting institutions (hand-built SVG, Equal Earth projection, Natural Earth land shapes from `assets/vendor/world/`, no map library). Institutions that sit close together at the current zoom are grouped into one larger green circle showing how many it holds (hover or tap lists the members with their counts); clicking or tapping a group zooms in so its members fill the view and separate (at the deepest zoom nothing is grouped, so institutions in the same city are drawn side by side), and groups re-form as the map is zoomed out. Each single institution is a white disc filled by its logo (seal, coat of arms or official icon; a monogram only if none is usable) inside a thin ring coloured by the share of its people with a verified first job; spellings of one institution that share a Wikidata item are one circle, with the other spellings named on its card; circle area is people in the dataset or verified first jobs; circles are nudged apart where institutions share a city, grow slowly as the map zooms and spread again when it settles. Region views (World, North America, Europe, Asia & Pacific), zoom buttons with animated zoom, Ctrl/⌘ + scroll, pinch, drag to pan, a size legend and serif labels for the largest institutions follow the Econ PhD Placements map. On devices with a pointer, hovering shows a card that stays open while the pointer moves onto it, so its profile, records and member links can be clicked, and clicking a circle opens the institution's profile; on touch screens a tap resolves to the nearest circle and shows the card below the map, with buttons to the profile and the records. A "By year" view shows each PhD institution's graduating classes as circles sized by people in the directory and filled by the share with a verified first job, with a table view of the same numbers. Charts are plain SVG (`assets/charts.js`) with hover and keyboard tooltips; the numbers come from `assets/analytics.js`, which always reports verified first jobs next to unresolved and not-yet-reviewed counts. The trends section shows verified first jobs over time (stacked by type, count or share, with a research-coverage layer that shows unresolved and unreviewed people per cohort), rankings of PhD institutions and fields by the share of a chosen job type (with minimum-size thresholds stated), and the top first employers; each view has period and type selectors, tooltips, a table view and click-through to the explorer. Profiles cover each PhD institution (people in the directory, verified first jobs, tenure-track and academic shares of verified jobs, unresolved and unreviewed counts, first jobs by type, top first employers, cohorts by research status, tenure-track share by cohort, employer countries and job titles), a head-to-head comparison of two to four PhD institutions, and each first employer (sources, titles, cohorts, recent hires linked to their evidence), all with cohort period selectors; the original directory-affiliation profile remains. `data/employer-locations.json` places verified first employers the same way as institutions (an employer written as a school of a university is placed at the university, a company at the headquarters its Wikidata item records, each recorded in the row), and `node scripts/wikidata-countries.mjs` adds each matched item's country to both location files. The explorer has a filter box under each column (name, PhD year or a range such as 2015–2020 or >2022, PhD institution, affiliation or employer with start year, position or type of job or field), a type-of-first-job selector in placements mode, and a shareable query string (`?q=`, `?mode=placements`, `?phd=`, `?employer=`, `?compare=A|B`, `?coverage=years`, `?trend=employers`) that reopens the same view. A Universities section shows the first database (universities with operations departments from the Operations Academia directory) with search, country and people-database link filters, each university's departments, its link to the matching PhD institution profile, a by-country chart, the counts of the merged organisation database and, per university, how many people its linked faculty page lists, how many of them are on OM List and how many are unverified. Each PhD institution and first-employer profile ends with the merged organisation record: its Wikidata item and country, its roles across both databases, a link to its other profile, its operations departments from the directory with faculty-page links, its registered programs and every spelling under which it appears. The explorer's name filters, the profile pick-lists and the search treat spellings that differ only in accents, punctuation, spacing or case as one organisation. The methodology section describes collection, structuring, validation, publication, classification and data availability, with the availability counts computed from the data at load time. Search by name, affiliation, PhD institution, discipline and research tags; filter by institutions, status, discipline or PhD years; sort and paginate. Institution and PhD-program profiles, comparisons of up to four institutions, and cohort and source-status charts use the same data. CSV exports neutralize spreadsheet formulas. All displayed source text uses safe text nodes.
