# Operations PhD Placements

Public website: https://www.stouras.com/opsphdplacements/

An independent, static research directory for Operations Research, Operations Management and Industrial Engineering. The visual organization is inspired by Econ PhD Placements; all application code is original.

## Deployment

Push to `main` to run the GitHub Pages workflow. The project inherits the account site's custom domain; do not add a CNAME pointing the domain at this repository. The workflow publishes `index.html`, `.nojekyll`, `robots.txt`, `sitemap.xml`, `favicon.ico`, `site.webmanifest`, `assets/` and `data/`.

## Data

`data/faculty.json` holds all 2,149 profiles from the OM List all-faculty snapshot of 16 October 2026 across 202 institutions. Source status (active, industry, retired or deceased) is preserved. PhD information is joined by exact source profile URL. `data/placements.json` holds independently verified first placements and contains the reviewed first-employer records published so far. Never infer a first placement from a directory affiliation.

See [DATA-PROVENANCE.md](DATA-PROVENANCE.md) for source reconciliation, reproducible import commands and limitations. The source does not cover Industrial Engineering departments; its discipline labels do not verify the subject of someone's doctoral degree.

## Checks and publication

Run `npm run check` with Node 22 or later. There are no application dependencies. The publishing script copies public files and versions assets to prevent stale pages after updates. Checks cover dataset identity and provenance, filtering, missing years, grouped counts, and safe CSV export. Every production deployment runs these checks. Only public assets are deployed; research snapshots, import tools and test fixtures are excluded.

Preview with a static server, inspect changes and commit the reviewed data. A push to `main` validates and publishes the site. Roll back by reverting a commit and pushing; never overwrite history. No scheduled scraping is configured.

## Data contracts

Faculty records require a unique stable `id`, `name`, `sourceUrl`, and `retrievedAt`. Unknown degree facts are null; a future doctorate year is flagged. Retain original source labels and source URLs. Faculty affiliation is not a placement outcome.

First-placement records additionally require `verificationStatus: "verified-first-placement"`, `evidenceUrl`, `reviewedAt`, and an explicitly known `placementYear` or null. Review the explicit first-job evidence before adding any record. Imported degree fields remain source-reported unless the corresponding field verification status says otherwise; verifying a job does not verify every directory fact.

`data/institution-locations.json` holds an approximate map location for each imported PhD institution, matched by name to a Wikidata item (its ID, label and description are kept so matches can be checked), plus the path of a small site icon under `assets/logos/`. Unmatched or ambiguous names stay unmapped and are counted on the map, never guessed. Regenerate with `node scripts/geocode-institutions.mjs` and `node scripts/fetch-institution-logos.mjs`; both are slow because Wikidata rate-limits anonymous clients. `data/institutions.json` and `data/employers.json` are derived databases regenerated by `node scripts/build-institutions.mjs`: one row per PhD institution (people in the directory, verified first jobs, unresolved and pending counts, cohort range, first-job types, top first employers, location, country, icon and sources) and one row per verified first employer (verified first jobs, source institutions, positions, cohorts, location, country). They are never edited by hand, and `npm run check` fails if their totals disagree with the public files. `data/doctoral-programs.json` holds the partial historical program register, with field-level sources/check dates and explicit unknown historical dates. It does not yet contain complete graduate rosters. Refresh `RESEARCH-STATUS.md` with `node scripts/update-research-status.mjs` when publishing data changes. Run `python scripts/test-research-schema.py` and `python scripts/build-research-database.py` for the relational evidence checks and reproducible snapshot.

## Features

The coverage section opens with an interactive world map of PhD-granting institutions (hand-built SVG, Equal Earth projection, Natural Earth land shapes from `assets/vendor/world/`, no map library): each institution is a white disc holding its site icon (or a monogram) inside a ring coloured by the share of its people with a verified first job; circle area is people in the dataset or verified first jobs; circles are nudged apart where institutions share a city, grow slowly as the map zooms and spread again when it settles. Region views (World, North America, Europe, Asia & Pacific), zoom buttons with animated zoom, Ctrl/⌘ + scroll, pinch, drag to pan, a size legend and serif labels for the largest institutions follow the Econ PhD Placements map. On devices with a pointer, hovering shows a card and clicking opens the institution's profile; on touch screens a tap resolves to the nearest circle and shows the card below the map, with buttons to the profile and the records. A "By year" view shows each PhD institution's graduating classes as circles sized by people in the directory and filled by the share with a verified first job, with a table view of the same numbers. Charts are plain SVG (`assets/charts.js`) with hover and keyboard tooltips; the numbers come from `assets/analytics.js`, which always reports verified first jobs next to unresolved and not-yet-reviewed counts. The trends section shows verified first jobs over time (stacked by type, count or share, with a research-coverage layer that shows unresolved and unreviewed people per cohort), rankings of PhD institutions and fields by the share of a chosen job type (with minimum-size thresholds stated), and the top first employers; each view has period and type selectors, tooltips, a table view and click-through to the explorer. Profiles cover each PhD institution (people in the directory, verified first jobs, tenure-track and academic shares of verified jobs, unresolved and unreviewed counts, first jobs by type, top first employers, cohorts by research status, tenure-track share by cohort, employer countries and job titles), a head-to-head comparison of two to four PhD institutions, and each first employer (sources, titles, cohorts, recent hires linked to their evidence), all with cohort period selectors; the original directory-affiliation profile remains. `data/employer-locations.json` places verified first employers the same way as institutions, and `node scripts/wikidata-countries.mjs` adds each matched item's country to both location files. The explorer has a filter box under each column (name, PhD year or a range such as 2015–2020 or >2022, PhD institution, affiliation or employer with start year, position or type of job or field), a type-of-first-job selector in placements mode, and a shareable query string (`?q=`, `?mode=placements`, `?phd=`, `?employer=`, `?compare=A|B`, `?coverage=years`, `?trend=employers`) that reopens the same view. The methodology section describes collection, structuring, validation, publication, classification and data availability, with the availability counts computed from the data at load time. Search by name, affiliation, PhD institution, discipline and research tags; filter by institutions, status, discipline or PhD years; sort and paginate; download the filtered CSV. Institution and PhD-program profiles, comparisons of up to four institutions, and cohort and source-status charts use the same data. CSV exports neutralize spreadsheet formulas. All displayed source text uses safe text nodes.

Source directory: https://omlist.edutool.org/faculty

Social sharing uses static Open Graph and Twitter/X metadata with a 1200 × 630 preview image. SVG/PNG/ICO favicons and Apple/mobile icons provide matching saved-link branding. See [SHARING.md](SHARING.md) for regeneration, validation and preview-cache limitations.

## Graduate census and career histories

[RESEARCH-DESIGN.md](RESEARCH-DESIGN.md) specifies the subsequent expansion to all documented graduates of in-scope programs, including industry careers and sector transitions. [database/schema.sql](database/schema.sql) defines the relational schema. Run `python scripts/build-research-database.py` to produce the disposable local snapshot `research/operations-careers.sqlite` from the public JSON, including people, source-reported doctorates, reviewed first-job events and evidence. JSON remains the source of truth during current collection; the generated database does not yet serve the website. Rebuilding replaces that derived snapshot, so do not edit it directly. No later appointments or degree programs are inferred. A historical program register, including closed and renamed programs, starts the graduate census; existing first-placement verification continues in parallel. The schema also supports advisor relationships, publication/authorship records, PhD-year publication assessments and per-fact check histories. These tables are infrastructure, not claims that all graduates or career histories have already been collected.
