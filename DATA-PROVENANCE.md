# Faculty data provenance

The website dataset in `data/faculty.json` contains all **2,149 unique faculty profiles** in the [OMList all-faculty directory](https://omlist.edutool.org/faculty) snapshot retrieved on **16 October 2026**. Every source section count matches its extracted row count.

| Source status | Records |
| --- | ---: |
| Active faculty | 2,101 |
| Industry and practice | 2 |
| Retired | 36 |
| Deceased | 10 |

The directory represents 202 affiliation institutions and classifies 1,853 profiles as Operations, 261 as Supply Chain Management, and 35 as Decision Sciences. These are subject classifications from the source, not verified doctoral degree subjects.

## Doctorate reconciliation

Doctorate institutions come from the [OMList PhD-by-year table](https://omlist.edutool.org/phd/by-year.html), joined using the exact profile URL. Its 2,604 rows match the total of its source year-section counts. There are 2,127 exact matches to the requested faculty directory, with no conflicting names, doctorate years or affiliations. The 477 doctorate-table profiles outside the faculty directory are excluded from the website dataset.

The final dataset includes **369 distinct known doctorate institutions**, **2,125 records with known doctorate institutions**, **2,127 reported doctorate years**, and **1,011 tenure years**. There are **22 missing doctorate years** and **24 missing doctorate institutions**. Of the latter, 22 have no matching doctorate-table entry and two have a literal placeholder instead of an institution. Placeholder values are normalized to `null`, with their original values retained in `sourceRawPhdInstitution` for provenance.

One reported doctorate year is 2027 and is flagged `future-year-in-source`, rather than represented as a completed PhD. The reported year range is 1953–2027.

## Reproducing the import

The two import scripts operate only on local files. They do not fetch pages, run a crawler, or create a scheduled refresh. Python 3 and BeautifulSoup 4 are required; the initial import used Python 3.13 and BeautifulSoup 4.13.4. Install the parser with `python -m pip install beautifulsoup4==4.13.4` if needed.

Place saved HTML snapshots in an input directory with these filenames:

* `omlist-faculty.html`: the requested faculty directory (`/faculty.html` redirects to `/faculty`).
* `omlist-phd.html`: the source PhD-by-year table.

From the repository root, reproduce the original import with:

```sh
python scripts/extract_phd.py --input-dir research --retrieved-date 2026-10-16
python scripts/extract_complete_faculty.py --input-dir research --retrieved-date 2026-10-16 --output data/faculty.json
```

Use the actual snapshot retrieval date for future imports. Both snapshots must have the same date. The scripts require `--retrieved-date`; `--input-dir` defaults to the repository's `research` directory. Both accept `--output`. The complete import also accepts `--phd-data` to select a doctorate JSON generated by the first script. Validate an import without replacing the website dataset by setting the second output to `research/faculty-preview.json`.

Both outputs use `{ "version": 1, "metadata": { ... }, "records": [ ... ] }`. The final metadata preserves separate source counts, source section totals, snapshot checksums, retrieval date, exact join counts, missing-field counts and source limitations. Checksums are SHA-256 of the HTML decoded as UTF-8 with an optional BOM removed and newline normalization, then encoded as UTF-8. The source snapshots are local research inputs and must not be deployed as website content.

The pipeline stops if declared source counts disagree with extracted counts, profiles are duplicated, no rows are found, retrieval dates disagree, or names, doctorate years or institutions conflict between the two sources. Review discrepancies before publishing updated data.

## Interpretation and limits

* **The original import does not establish first placements.** Its `firstPlacement` and `firstPlacementYear` stay `null`. Separately researched results are published in `data/placements.json`; `data/research-status.json` tracks verified, unresolved and pending research for all 2,149 profiles.
* The institution field preserves the source's directory affiliation. For retired, deceased or industry profiles, it must not be presented as a current active faculty appointment; the status is retained explicitly.
* A missing professional title is stored as `null`; an institution name is never substituted for an omitted role.
* [OMList's methodology](https://omlist.edutool.org/methodology.html) states that it focuses on business schools and excludes Industrial Engineering departments. This import is complete for the requested directory snapshot, not the OR/OM/IE profession.
* Facts are marked `source-imported` and have not been independently checked against university biographies. Research tags are the source's classifications. No doctorate degree title is inferred from an affiliation or research area.
* Names, professional titles, faculty status, affiliation, doctorate institution/year, tenure year, research tags and source links are retained. Contact information, inferred demographics, paper abstracts, copied biographies and research scores are excluded.

The public directory was processed locally from an already-downloaded snapshot at the user's request. No school/profile pages were crawled and no login, CAPTCHA or technical access controls were bypassed. The site's [robots.txt](https://omlist.edutool.org/robots.txt) discourages general crawlers from `/faculty.html` and `/schools/`; any future acquisition process should account for that guidance. These scripts contain no network acquisition or autonomous crawler.

## First-placement verification

Researchers inspect explicit initial-placement reports and dated employment histories in public CVs and university biographies. The first post-PhD appointment may be a postdoc or fellowship. Later faculty appointments must not displace earlier jobs. A source listing only a university supports an employer, not a tenure-track classification. A graduating cohort label does not establish an exact employment start date.

Each published result includes its supporting URLs, short paraphrased evidence, review date, and any reconciliation of conflicting degree information. Exact job title, category or start year remain unknown where not established. Original imported degree facts are retained alongside verified corrections. Current affiliation is never used as a substitute for first employer. Partial results are not representative employment shares.

The public research ledger distinguishes genuinely reviewed unresolved cases from pending cases; finding a CV URL alone does not constitute verification. Merge reviewed agent results with `node scripts/merge-placement-research.mjs research/placements-a/results.json research/placements-b/results.json research/placements-c/results.json`, then run `npm run check`. The merge checks identity, evidence, categories and degree-year discrepancies; the deployment validates that the ledger covers every imported person exactly once.
